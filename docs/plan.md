一、 硬件与基础环境（定海神针）
显卡确认：GTX 1650 Ti（笔记本版），显存通常为 4GB。请务必在任务管理器或 nvidia-smi 中确认，绝对不是6GB。

精度模式：首轮训练使用 FP32（单精度），优先保证稳定性和便于排查问题。训练流程稳定后，可单独测试 FP16/AMP，但不作为必需配置。

深度学习框架：推荐使用支持 Python 3.11 的 PyTorch 2.x。安装带 CUDA 11.8 或 CUDA 12.x 运行时的版本即可，当前 NVIDIA 驱动无需额外安装 CUDA Toolkit。

二、 数据与输入层（地基）
原始数据：当前有两组多局棋谱集合：`data/raw/dpxq-99813games.pgns` 和 `data/raw/WXF-41743games.pgns`，合计约 141,556 局。文件内容是 PGN 风格的多局文本容器，`.pgns` 不是需要直接交给国际象棋 PGN 库的标准扩展名；每局由元数据区、FEN 和着法区组成。

格式调研结论：本地样本明确包含 `[Format "ICCS"]`。ICCS（International Chinese Chess Server）是中国象棋坐标记谱，不是中文“炮二平五”记谱。例如 `C3-C4` 表示从 C3 走到 C4；列为大写 `A-I`，行号为 `0-9`，中间通常用连字符分隔。不能依赖文件后缀判断格式，必须读取 `Format` 标签并按 ICCS 解析。

元数据处理：保留 `Game`、`Event`、`Date`、`Red`、`Black`、`Result`、`Opening`、`FEN`、`Format` 等标签，至少记录来源文件和棋谱编号，便于追溯和去重。忽略空行、注释和结果标记（如 `1-0`）；只接受合法的 ICCS 四字符着法。

预处理目标：从每局的起始 FEN 逐步执行 ICCS 着法，生成每一步的 `(position, from_square, to_square)` 样本，而不是只生成一条 `(FEN, 中文走法)` 对。每执行一步后更新棋盘，下一步样本使用更新后的局面。

坐标转换：ICCS 的列 `A-I` 映射到 `0-8`，ICCS 行 `0-9` 映射到棋盘行 `0-9`；由于 FEN 从黑方一侧开始描述，固定使用 `fen_row = 9 - iccs_row`。棋盘张量统一使用 ICCS 行顺序，避免不同模块重复翻转。起点和终点都编码为 `0-89`，分别作为双头输出的标签。

数据清洗与验收：逐局解析时校验 FEN、ICCS 着法格式、轮次和局面连续更新；棋谱来源已确认合法，不在数据准备阶段重复实现走子合法性验证。遇到格式损坏时记录文件名、局号和原因并跳过该局，不得静默丢弃。统计每个集合的总局数、成功局数、失败局数、生成样本数、重复局数和结果分布，先抽样打印棋盘与前 10 步转换结果人工核对。

数据分割：按棋局而不是按单步样本划分训练集和验证集，防止同一局的相邻局面泄漏到两个集合。合并两组集合前先按规范化的元数据和完整着法序列去重。

棋盘编码（核心）：

输入张量：第一阶段形状为 (15, 10, 9)，包括红方7个棋子通道、黑方7个棋子通道和1个当前行棋方通道。14个棋子通道对应帅/仕/相/马/车/炮/兵，10行9列对应棋盘。不能省略当前行棋方，否则同一棋盘在不同轮次的含义无法区分。

走法编码（第一版基线）：采用双头输出，即起点头（90类）和终点头（90类）。两个头独立预测可能产生非法组合，因此推理时必须使用合法走法生成器过滤和重新归一化。后续再比较条件终点头或直接对合法走法建模的策略头，不能仅凭动作类别数量判断方案优劣。

合法走法掩码：数据准备和监督训练不重新生成合法走法 mask，起点和终点头直接使用已确认合法的 ICCS 标签计算交叉熵。推理阶段仍需由独立的棋规模块生成合法走法集合，将合法的 `(start_index, end_index)` 作为动作 mask；这属于推理/搜索约束，不是数据准备门槛。

数据预处理：解析和校验只在离线脚本中进行；训练前将局面张量、起点标签、终点标签和必要的样本元数据转为 `.npy` 或 `.npz`，存入 NVMe SSD。训练循环禁止实时解析 PGN、ICCS 或 FEN 字符串，否则 CPU 会成为瓶颈，显卡可能空载。

数据准备步骤和产物：详见 [数据准备计划](data_preparation_plan.md)。

三、 模型架构（瘦身求生）
针对4GB显存，必须使用 Tiny-ResNet（微型残差网络）：

残差块数量：4个（标准版是6~10个，你承受不起）。

卷积核数量（Filters/通道数）：64（标准版是128~256，你承受不起）。

参数量：目标控制在约 80万 ~ 150万之间，以实际模型统计值为准。

输出层：策略基线使用两个独立的全连接层（FC），分别映射到90类（起点）和90类（终点）；当前已支持第三个价值头，输出当前行棋方视角的局面价值（胜为+1、和为0、负为-1）。

四、 超参数与训练配置（核心旋钮）
Batch Size（批次大小）：策略基线默认16；当前 GTX 1650 Ti 环境可先尝试 value head 使用512，实际训练仍应以显存峰值为准。

梯度累积（Gradient Accumulation）：小 batch 时设置为8；当 batch size 为512时设置为1。

原理：多个小 batch 的梯度累积后再更新参数，可近似获得更大的有效 batch；学习率调度器只在实际执行 optimizer.step() 后更新。

学习率（Learning Rate）：初始设为 0.001。

优化器：AdamW（比传统Adam泛化性更好，适合小显存调参）。

学习率调度（LR Scheduler）：使用 CosineAnnealingLR 作为单次余弦衰减基线；它不是周期性重启调度。调度器只在实际执行 optimizer.step() 后更新，`T_max` 按实际 optimizer 更新次数计算，而不是按 DataLoader 小批次次数计算。

轮数（Epochs）：设置 100，但必须配合下面的早停法。

五、 训练流程与防崩机制（保命符）
早停法（Early Stopping）：必须加。统一监控验证集（Validation Set）损失，设置 Patience=5，并保存验证损失最低的 checkpoint。实际停止轮数和总时长以实测为准。

数据划分：推荐按棋局或更高层级分组，使用 80% 训练集、10% 验证集和 10% 封存测试集；验证集只用于早停和调参，测试集只在最终模型确定后使用。若当前阶段只生成训练集和验证集，则使用 90%/10%，但不得把验证集反复当作最终成绩。

数据增强（白嫖棋谱）：数据准备阶段先导出未增强的规范数据；训练 Dataset 只对训练集做左右水平翻转，并同步翻转 ICCS 列和起点/终点标签，不能做上下翻转。验证集和测试集保持原始分布。若 CPU 变换成为瓶颈，再单独生成带版本和来源索引的训练镜像缓存。

类别权重：第一阶段默认不启用，先使用普通交叉熵建立无偏基线。只有分段指标确认低频走法明显失真后，才通过加权或重采样做对照实验，避免破坏真实棋谱分布和概率校准。

评估指标：除 validation loss 外，必须记录起点、终点、完整走法的 Top-1/Top-5 准确率，以及合法走法 Top-K 命中率；同时按开局/中局/残局和红方/黑方分段统计。最终用固定时间控制与 Pikafish 对局或胜率评估实际棋力。

加载器（DataLoader）：先设置 num_workers=2 进行测试；如果 Windows 下出现启动、内存或稳定性问题，再退回 0 或 1。

六、 时间与性能预期（心理建设）
单轮耗时：首次先跑一个完整 epoch 做基准测试，再据此估算总时长（取决于数据量、CPU、SSD 和 GPU 利用率）。

总训练时长：利用早停法，暂估 2.5 ~ 3.5 天，必须以基准 epoch 的实测结果重新校准。

禁止事项：第一阶段不要引入 CNN+Transformer 或更大的 ResNet；不要在训练时打开其他占用显存的软件。模型增强应通过可重复的对照实验决定，而不是预先绝对禁止所有替代架构。

七、 推理与部署（赛后检验）
训练完成后，模型文件大约 20~30 MB。

推理速度：先以“生成全部合法走法并逐一评分”为正确性基线，再通过 benchmark 决定是否需要候选剪枝；不能预先假定 2-3 毫秒。确认速度后，再评估是否足够支持后续蒙特卡洛树搜索（MCTS）。

总结一句话：
先用15通道输入和 Tiny-ResNet（4块、64通道）完成策略基线；现有 processed 数据可直接补充 values.npy，再从零训练带 value head 的模型。确认价值指标后，再接入 MCTS 和自我对弈。
